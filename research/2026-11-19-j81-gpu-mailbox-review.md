## Which evidence would change the next decision?

1. **Recover the existing iPadOS attempt first.** Search a retained device unified-log archive covering the read-probe boot, including info and debug records. The live syslog's silence does not establish what persisted on the device. Record the boot UUID, source, timestamp and full message. A collector from a different boot, host preparation messages, a malformed value, or a map-failure sentinel cannot supply the missing measurement. If the archive lacks the marker, report its coverage and how the attempt was identified.
2. **Interpret the first valid value at its actual phase.** A set bit documents that it was set on return from the enable call. A clear bit documents that it was already clear at that instant, subject to boot attribution and a successful mapping. Neither result measures retention through startup or a dependency of page-5 bit 30. The next iPadOS comparison is a later pre-GPC read with a known GPC/page-5 outcome in the same boot. A different boot's successful core ID cannot fill that column.
3. **Continue the Linux paired comparison independently.** On one observer boot capture the setter sequence, candidate words after the cycle and before GPC, the GPC poll, and the two timed page-5 values. Preserve missing samples as unknown. The outstanding clock-word packet and the observer-matched paired run have no result in these four returns.
