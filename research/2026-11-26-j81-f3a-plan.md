Status: F2 is done (run 44: Apple's full sequence incl. the real override release passes with module h32). F3a is the first run that lets META execute Apple's firmware. Nothing here has been built or run. Sources: requests 4 (`2026-11-22-j81-ldr-tool-fwif-result.md`, `...gpu-appendix-t2-ddk.md`), 7 (`...meta-boot-research-result.md`), 12, 13 (`...request13-t2-boot-sequence.tsv`, `...t3-next-boots.tsv`).

## What the run must do (Apple's order, request 13 t2)
GFX PS power cycle + bridge re-apply (h3pb) -> state 0 -> `+0x10 = 0`, `+0 = 0x40000000` -> ConfigRAM stream (SOFT_RESET x3, META_BOOT <- 1, **BIF_CAT_BASE0 <- page-catalogue phys**, SLC pair, SOFT_RESET <- 0, terminator) -> `+0x20000 = 0` -> `+0x1000 = 0x11` -> walk at 0->1; META boots itself from GPU VA `0xe1c0000000` -> firmware posts a type-0 event record (word +4 = idle PC) and raises AIC IRQ 138. Host reads no RGX register while waiting; detection is a memory poll of the event-ring write index (event ctl +0x10 != +0).

The only new ingredients versus run 44 are (a) the memory image the GPU reads and (b) the real BIF_CAT_BASE0 entry in the list.

## Design

**D1. Firmware image source.** The 19H394 J81 `AGXFirmwareKextG4G` LDR (117,684 bytes, `__TEXT.__const`, provider `0x59ab9c8`, size `0x1cbb4` per request 8; sha256 `55018c7e...092c2f`) must be extracted from the 19H394 kernelcache on the NAS (`firmware/ipsw/extracted/*15.8*/kernelcache`). Firmware bytes stay in a private, git-ignored directory; only hashes are committed. Open: confirm I can locate that kernelcache and the image offset (I have not yet; the tool refuses a directory inside a git work tree).

**D2. Memory.** The GPU MMU is Imagination's BIF, not a DART (request 7): physical addresses go straight to DRAM. The module allocates one physically contiguous region (target 8 MiB: buffer 0x212b4, rings and blocks about 0.5-1 MiB, page tables, slack), reports its physical base through sysfs, and the image is built *for that base* (the page catalogue entry needs real physical addresses). Flow, one boot:
1. new module step `f3a_alloc`: allocate, zero, print phys base and size;
2. host-side builder `boot/j81_f3a_build.py` (wraps `tools/j81_meta_ldr_layout.py`) produces one blob (page tables, firmware buffer, root/state/config, blocks, rings, ConfigRAM word list with the real CAT_BASE phys) for that base;
3. runner uploads the blob through a sysfs binary attribute; step `f3a_load` copies it in and flushes caches.
Alternative if contiguous 8 MiB is not allocatable: smaller region or `memblock`/CMA; decided by `f3a_alloc` result (it is a pure-memory step and safe to try).

**D3. Cache coherency (risk).** Fender `+0` bit 29 is "SNOOP" (cleared by our `+0 = 0x40000000`; Apple's direct-access check also requires it clear). Whether GPU DMA snoops CPU caches on A8X is unknown. Mitigation: allocate with `dma_alloc_coherent`/uncached mapping for the state block (Apple maps it uncached), and flush (`dcache_clean_poc`) the whole region after the load for the rest. Poll the event ring through an uncached mapping.

**D4. GPU page tables.** One context, 4 KiB pages: PC (1024 x u32), PD (512 x u64), PT (512 x u64) per 2 MiB. The firmware heap (`0xe1c0000000`, 2 MiB aligned) needs one PC/PD/PT chain; every firmware object lives inside it. Entries: PC `((PD>>12)<<4)|1`, PD `PT|1`, PT `pa|1|flags` (appendix-t3). The config block's 9-entry MMIO window table (Fender 0x5000, RGX 0x20000, AIC SW-int, AIC timer; entries 4-9 unresolved) needs those pages mapped in GPU VA too: map the known four, leave the unresolved entries zero (risk: firmware may fault on them; BIF fault regs tell us).

**D5. Detection and abort.** Poll the event ring (uncached) every 1 ms for up to 10 s; stop at the first non-zero write index. No MTS kick, no META slave-port access, no RGX reads beyond the h11 safe set before alive. Afterwards read, in this order, only if alive was seen: `0xbf8`, BIF fault `0x12b0`, T0ENABLE via the slave port is NOT used. Run ends with a reboot (one shot per boot), so there is no stop path in F3a; the supervisor watchdog resets the iPad if the module hangs.

## Staged steps (one variable each, one boot each)
- **F3a-0, memory only (no Fender, no walk):** `f3a_alloc` + upload + `f3a_load`, then a read-back checksum of the region and a dump of the page-table walk for `0xe1c0000000`. Proves allocation, upload, and that the image is self-consistent offline. Risk: none.
- **F3a-1, catalogue lands, META stays in reset:** run 44's sequence with the real list but **without the final `SOFT_RESET <- 0`** (META never starts). At h11 read `0x1200` (BIF_CAT_BASE0; safe-read status unverified, so read it only after reading `0xbf8`, and treat a hang as an answer) and `0xbf8`. Proves the catalogue base write and that a non-empty list with BIF_CAT_BASE0 is harmless. Risk: low-moderate.
- **F3a-2, the real run:** full list including the final release, then the event-ring poll for 10 s. Pass = type-0 record (word +4 = idle PC). Fail modes and what each tells: no record and no fault (firmware not running or stuck before alive), BIF fault status set (page-table/window problem), iPad reset (watchdog; run ends INCOMPLETE).
