# J81 iOS page-5 PMGR store tracer

Experimental 19H394 extension of the [five-point probe](../j81-page5control/README.md). It preserves those five reads and adds a passive hook at the candidate ordinary PMGR writer's displaced store `bd0538`. The hook executes the original store once, captures bounded metadata, and does no extra MMIO, logging, allocation or sleeping. It watches only the saved PMGR object, ordinary region 0, offset `0x5004`, instance 0. The bridge writer uses a different mapping table and is not watched. The live object's class and mapping are not independently verified.

The coarse phase is `0` before the control sample begins, `1` from immediately before the control sample until immediately after the successful post-GPC-poll sample, and `2` thereafter. Phase publications enclose the two reads, not the physical GPC write or hardware transition. At the later identity hook, the existing samples are logged along with:

- `Z=<phase>:<seen>:<count>:<overflow>`: four eight-digit hex values. `seen=1` means the patched store site executed at least once, including unrelated stores; it is a positive control for reaching the hook, not proof every possible call was observed. `count` is the number of reserved matching entries, capped at 16. `overflow=1` means capacity or bounded reservation contention was exceeded.
- `W=<before>:<after>:<value>`: one successfully published matching store record. Before and after are phase values read on either side of the displaced store. A different pair means the store crossed a software phase boundary. A record shows execution continued after the store instruction, not that the device accepted or retained the write.
- `W=UNREADY`: an entry was reserved but not published when the logger inspected it. The corresponding result is inconclusive.

The tracer records matching entries from all phases after the saved object is available, not only phase 1. A `W` record with both phases 1 is associated with the broad observation window, but concurrency and delays prevent attributing the hardware bit change merely from that fact. Events at boundaries can be ambiguous; an interrupted writer can be delayed before reserving an entry, including until after the logger snapshots the count. Thus **zero entries cannot prove no matching store occurred between the samples**. Missing C/M samples, phase not 2, `seen=0`, overflow, unready entries, or loss of boot logs are inconclusive. These flags do not eliminate the pre-reservation race. Other CPUs, interrupt paths, direct stores, aliases, different objects, firmware and autonomous hardware remain possible.

Same Pongo environment as the earlier control probe, component `j81_page5writer_capture`, flag `KPF_CFLAGS=-DJ81_PAGE5WRITER_DEVICE_BUILD`. Existing five undocumented reads remain; they and global store instrumentation can perturb timing, hang or reboot. No hardware run has been made.

The exact kernel passed the positive KPF harness and each of twelve missing and duplicate signatures plus wrong UUID was rejected. Native ARM64 host simulations exercised five-sample behavior, target filtering, actual displaced-store effect, concurrent reservations, overflow, completed publication, deliberately unready entries and simulated phase crossing. A static check verifies one displaced store, saved scratch registers/NZCV and bounded reservation attempts. These tests use mocked context and do not establish real kernel stack headroom, exception behavior, object lifetime, physical mapping, MMIO side effects or cross-CPU timing. An independent review is warranted before any device run.
