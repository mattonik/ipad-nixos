# What to measure after the J81 five-word replay

**T1 — startup before the hook.** [Code] The CPU performance controller, PMGR resource 1 at 0x202220000, receives conditional TVM/DPE requests and a late subclass update to +0x20. The J81 ADT identifies the SGX core and Fender resources, clock-gates, power-gates and gfx-qos. PMGR declares bridge-reg-index, bridge-settings-0 through -12, cpu-tvm, soc-tvm, dpe-thrtl and function-mcc_ctrl. See the exact 19H394 ADT property inventory and CPU site table in the share packet. Resource declarations alone do not order XNU services. A complete executed order through platform expert, AIC, timer, MCC, DART and PMGR could not be recovered from these captures.

**T2 — CPU state.** [Code/observed] Several implementation-defined register masks are identifiable in 19H394 early init (VA suffix 713736c..73d0). Linux's effective MAIR byte for the core aperture was 0 on mapping boot caacf910, matching the static iPadOS prediction. A phase-matched iPadOS leaf or paired CPU implementation-register capture is missing. See the SPR table. No specific CPU workaround has been shown to govern this read.

**T3 — loader writes.** [Code] Four loader reports resolve 1,530 write references outside PMGR region 0. None resolves to 0x201000000..0x201ffffff. This includes both SGX resources and both bridges. Indirect writes can escape the reports. The returned TSVs give original addresses, source rows, operands and available value evidence, plus candidate MSR sites. Instruction address order cannot establish executed order or J81 branch outcomes. See the loader table for the image-specific counts.

**T4 — between power and ID.** [Code] Exact 19H394 VA suffixes 6683918..668394c dispatch provider slots +568 then +570, inferred clock and power. The enabled GPC path writes Fender +10000=ffff0000 and +0=40000000 if the bit-3 guard is clear, writes +1000=11, polls bit 4 clear, delays 10 µs and dispatches identity slot +a38 via the core mapping (6683978..66839e4). No additional direct fabric write appears in that interval. Provider side effects remain possible. This is the native driver path. The successful early observer is independent evidence that the aperture already responded at the earlier hook. See research/2026-11-08-j81-ios15-g4g-pre-id-clock-power.md for the mapping and +20/+18 identity offsets. The CPU results contain low-word zeros on three separate boots. The CPU table distinguishes conditional writes, access widths and same-boot observations.

The four missing same-boot full iPadOS bank readbacks, unnamed clients behind bit 31, unresolved indirect loader stores, CPU register retention, and order of unrelated XNU service starts remain open. If CPU +68 is positive, narrow the three zeros to the individual registers and their width/guards. If it is zero, establish CPU mapping and width before interpreting DPE or TVM.
