## T4 — Boot hand-off evidence by phase

[Observed] Bare Pongo, before m1n1 or Linux, already failed to return a word from 0x201000020 after 66 bridge stores and a GPC sequence. Its page-5 samples were still zero, perf=80110100, GFX voltage code=0. The later Linux replay failed with page 5 high and code=164. A change unique to m1n1/Linux cannot alone explain both failures; their immediate electrical conditions may differ. On iPadOS at the end-of-start manual sequence, the recorded revision was 00070500. Sources: research/2026-11-16-j81-pongo-core-read-result.md, 2026-11-14-j81-ios-boot-bisect-probe1-results.md run 3, and from-builder/2026-11-20-j81-linux-pll-write-result/RESULT.md. No trace spans the final loader instruction through m1n1 entry on a single boot.

| Stage | Evidence and useful boundary |
|---|---|
| 19H422 iBoot/LLB and 12B410 | [Code] All four resolved inventories contain a clear of bit 31 at PMGR +22000 (respectively 870015824, 180391534, 87a197be0, 180393eac) and no resolved write in 0x201000000..201ffffff. 19H422 iBoot/LLB contain zero stores to MiscACG (87001528c/180390f5c). 19H422 LLB has both set-bit31 and clear paths for perf +1c200 (1803907f8/180390f48). Its +22090 and higher tuple payload assignments at 180390a58..ab8 agree with six captured Linux values. The analysis establishes potential writers, not last-writer order. The loader releases differ from the kernel used for the successful hook. See previous from-builder/2026-11-20-j81-boot-path-diff-result/bootloader-inventory.md and research/2026-11-09-j81-llb-indirect-pmgr-helper.md. |
| Pongo | [Code] The boot path in the source matching its version string configures AIC/UART, SEP mailbox and peripheral gates. PMGR init parses ADT. No direct SGX, GFX bridge or MCC cache setup was identified. [Observed] Pongo saw +23000=f01; iPadOS end-of-start saw 1. These are different phases and boots. Sources: research/2026-11-09-j81-pongo-m1n1-pre-linux-writes.md and 2026-11-14-j81-ios-boot-bisect-probe1-results.md. |
| Hoolock m1n1 d5a10ac | [Code] pmgr_init can raise parents of already-on PS devices. MCC setup does not recognize mcc,t7000. The examined static tunables have no T7001 GFX path. CPU state 2 is an intermediate request, and the T7001 policy requests 7 at the end. Cluster base 0x202200000 is not the command word address (performance-controller resource at 0x202220000). The source does not establish actual CPU state during the later MMIO sample. Sources: above m1n1 audit, research/2026-11-19-j81-pmgr-start-resources.md, and pinned src/cpufreq.c. |
| Linux baseline and staged replay | [Observed] Linux boot 5372aa58 S0 shows GFX PS=300, MiscACG=0, +2d000/+2d100=0/0, PLL1/4 +8=80480348/88480348. After staged writes, PLL1/4=40480348/48480348, both TVM words=1, GFX PS=3ff; GPC changes perf to 80110100, +2300c to 164 and page 5 to 40000000. +23004 varies 170/180 across stages. The later 36e22c25 capture adds all five bank bits and still fails. These are Linux before/after observations. Attribution of the initial values to a particular loader or Linux service is unresolved. Sources: linux-pll-write-result/RESULT.md and linux-mcc-write-result/RESULT.md. |
| XNU pre-hook counterpart | [Code and observed] Parent startup commands PLL1/4, bank, MiscACG and voltage setup. Captures read MiscACG=0 on entry and 1 after enableACG on separate boots; +23000 is 1 at successful end-of-start. Apple uses masked updates and seeds CPU/SRAM fields from tables, while m1n1 writes the explicit voltage-control word. Matching +23000 does not establish matching rail voltage, past trajectories or state requested through another service. See research/2026-11-19-j81-pmgr-start-resources.md and 2026-11-19-j81-misc-acg-and-page5.md. |

[Inference] To attribute an overwritten value, prefer archived snapshots or an existing read-only stage diagnostic at Pongo before m1n1, m1n1 before Linux, and Linux before manual replay. Repeat only already-readable +23000, +23004, +2300c, +32000, +20320 and +1c200, with boot ID, phase and CPU. A first differing stage constrains attribution without identifying a GPU rail. Retrieve matched-build loader inputs and source revision for exact booted m1n1 if available. No demonstrated loader-only release of the core aperture, analog rail measurement, or specific m1n1 reset of that aperture was recovered.
