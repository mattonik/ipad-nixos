# J81 Linux DWI-on before the GFX activation, no-core control (prepared, not run)

Follows [the DWI snapshot result](2026-11-21-j81-dwi-snapshot-result.md): the observer has `dwi` off (PS 0x200) and the GFX voltage request (0x2300c = 0x164) never reaches the PMIC (buck 1 `0x0128` stuck at `00 00 40 00`).
This run switches `dwi` on first, then repeats the same no-core control and samples the same PMIC rows, to see whether the request now reaches the PMIC.

What: runner `artifacts/live/private/j81-linux-dwion-experiment/runner/boot` + the existing `j81-nocore-bundle-20261121` (module `4827876e...`, no core read; no rebuild). Inserted between the TVM store and the GFX activation:
`/tmp/pmgr-dwi-on` (the Nov 11 tool, `boot/pmgr-dwi-on.c`, sha256 `0fa252375e7fb1d97b64adf55e4cb0b4f7420906ac942163a78728456ab65258`, pinned) with host acknowledgement: it reads PS 0x20e020120; the runner refuses to write unless it reads exactly `0x00000200`
(target 0, actual 0); then ONE store (`v | 0xf`) and a poll for actual 15; the runner requires `result=on` and readback `target=15 actual=15`. Then a snapshot (SDWI) and `check_step` against S5: any other changed PMGR word stops the campaign BEFORE the GFX activation.
The rest is the DWI snapshot campaign: `DWI PS` in S0/S5/SDWI/A/C/D10, `GFX VID`, PMIC rows 0x0100/0x0128/0x0150/0x01c8 before the batch, after it and 10 s later (via `pmu-peek`).
Only new write: the one DWI power-state store (done on this board on Nov 11; the voltage manager then drives the CPU/SRAM rails through DWI as it did there). No core access. Flow test (including `dwi-not-on`, `dwi-already-on`, `dwi-changes-state` stops) and `--verify-only` pass.
The flow test caught a real bug in my first version (the runner could refuse after the read line arrived before the write prompt); fixed before any run.

Reading: buck 1 `0x0128` follows to `64 .. 64` after the batch with DWI on -> the request reaches the PMIC; then run the core-read variant on the same recipe (module `d9398f84...` or the plain compressed module with the core load).
Bytes unchanged (`00/40`) with DWI on -> the transport is on but the GPU request still does not arrive (look at the DWI request path / "GFX VID" consumers); a failed DWI-on or a changed PMGR word stops the run safely with the reason in `dwi-on.log` / the error.
Launch: fresh DFU cycle, same two boot commands with the `j81-nocore-bundle-20261121` boot files, preflight GO, go-ahead, then from the runner dir
`python3 j81_observer_paired_campaign.py <new logdir> --bundle ../../../j81-nocore-bundle-20261121`.
