# Mapping-only observation: plan (prepared 2026-11-20, not run)

Why: the GPU core-ID read (0x201000020) hangs on every Linux attempt (late read, timed read, and with MiscACG + soc-tvm both set) while every register compared so far matches the working iPadOS boot. The research packets (core-aperture, core-map) name the CPU translation of the core aperture as the remaining candidate that no archive can settle: no runtime translation record survives for any boot. This run records it, touching nothing on the GPU.

What it does (read-only, no device register access, one shot per fresh observer boot): `boot/j81-map-probe.c` opens /dev/mem O_RDONLY|O_SYNC and mmaps three physical pages exactly as `gpu-core-id-gated` does (length 0x1000, PROT_READ, MAP_SHARED): page 5 (0x20e005000) and GPC state (0x201e01000), both read successfully before, and the core page 0x201000000. It never dereferences a mapped address (disassembly checked: the only 32-bit stores go to the stack string buffer). For each mapping it writes the virtual address to `/sys/devices/j81-map-walk/va` and reads `.../walk`; the module `kernel/j81-map-walk/j81-map-walk.c` walks `current->mm` (this process) and prints VMA flags, `vm_page_prot`, raw pgd/p4d/pud/pmd/pte values, the leaf level, output physical address, AttrIndx, MAIR_EL1 and the selected MAIR byte, shareability, AP, AF, nG, PXN, UXN and TCR_EL1. The module's only hardware access is reading MAIR_EL1/TCR_EL1 and page-table entries.

Test: `boot/test_j81_map_probe_campaign.py` passes.

Expected under the kernel source (arm64 `phys_mem_access_prot` gives Device-nGnRnE for non-RAM pfns): all three leaf PTEs identical except the output PA, attr_idx selecting MAIR byte 0x00, PXN/UXN set, level pte, PA equal to the requested page. Outcomes: (1) core differs from page5/gpc-state in PA or attribute -> the mapping is the difference; (2) identical -> the CPU translation is not the difference, attention moves to downstream clock/reset/Fender state, the page-1/page-4 words, CPU TVM, DPE; (3) core `not-mapped` -> mmap populated nothing for that page (also informative). A hang is not expected: nothing reads the device.
