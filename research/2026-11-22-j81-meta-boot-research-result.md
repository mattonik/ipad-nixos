# Research packets 5 and 7 result: stock path from core-ID to running META firmware (2026-11-22)

Source: `builder-mailbox/from-builder/2026-11-22-j81-meta-mtp219-boot-result/` (identical to `...-rgx-post-id-result/`; RESULT.md, 8 tables, 2 appendices; checksums verified). Offline static analysis of the 19H394 kernel and kexts; nothing observed executing; treat as claims (tags in the source: code, adt, capture, upstream-claim, inferred). No firmware bytes in the result.

- **Firmware image (strong):** plain Imagination META LDR stream in AGXFirmwareKextG4G `__TEXT.__const`, 117,684 bytes, no signature/compression, two ELFs (thread 0, thread 1). 88 records: 67 LOADMEM, 13 ZEROMEM, 2 CONFIG (27 register writes), 1 START_THREADS (T0 PC 0x10000000 SP 0x8000a3c8; T1 PC 0x20000000 SP 0x8000b3c8). About 21 KiB of code goes to coremem at 0x80000080; the rest sits in DDR behind the GPU MMU (4 segments).
- **Start sequence (host side strong, META-side inferred):** SOFT_RESET staged 0x00e7fffffffffc1d, 0x00e7fe071ffffc1d, 0x1_00000000; META_BOOT (0xbf8) <- 1; BIF_CAT_BASE0 (0x1200) <- page-catalogue physical address; SLC_CTRL_MISC (0x3800) <- 0x0003550000300001 and 0x3808 <- 1; then SOFT_RESET <- 0 and GPC state 1 (the same 0x11 request the recipe does); then wait for "alive". The host never writes META memory or thread PCs; META boots itself from 0x40000000 and runs the loader list.
- **Fender proxy (risk):** when a global bit is set (J81 default) stock sends RGX register writes through a Fender/GPC mailbox instead of storing directly. Whether direct writes land on J81 is unknown (test W1).
- **Address space (strong):** Imagination's own BIF MMU, not a DART. 3-level page tables (PC 1024x4, PD 512x8, PT 512x8; entries given in appendix-t3-mmu.md). Firmware heap at GPU VA 0xe1c0000000. Our read of MMCU_SEG0 0x08000f02/0x17fff000 is the hardware default, not Apple's values.
- **Interrupts/handshake:** AIC IRQs 134-138 (138 = firmware-to-host software doorbell); host-to-firmware kicks via MTS_SCHEDULE 0xb00; "alive" is an event-ring record, not a register.
- **FWIF is Apple's own:** upstream's firmware init and boot-wait cannot be reused; reusable: LDR parser, slave-port access, SOFT_RESET/META_BOOT/BIF_CAT_BASE programming, MMU format, MTS values.
- **Unresolved:** META_BOOT at reset, Fender mailbox details, page size (12 vs 14), segment tuple DM field and buffer placement, the contents of the 0x1490/0x2058/0x990/0x8e0 blocks (without them a firmware run will not complete its handshake), seg2 meaning. Needs a decompiler pass (Ghidra) over named addresses, plus hardware runs R1 and W1.
- **Proposed steps (t5-steps.tsv):** R1/R2 reads (META_BOOT, BIF_CAT_BASE0, SLC regs, segment registers), W0 build page tables/firmware buffer in memory only, W1 first write (META_BOOT rewritten unchanged), W2 SOFT_RESET staging, W3-W5 META_BOOT, CAT_BASE, SLC, W6 release and observe T0ENABLE, caches, TxPRIVEXT, BIF fault status, IRQ 138.
Our coremem read at 0x80000000 (high-entropy, aliased) is consistent with unloaded coremem: stock loads code from 0x80000080 and zeros at 0x8000a000+.
