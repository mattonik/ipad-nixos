# J81 DPE throttle and the stalled GPU-ID load

On the 19H394 J81 device tree, the PMGR property `dpe-thrtl` is 12000 (0x2ee0). ApplePMGR uses the full value as a calibration-table key, and its nonzero status as an enable request. All identified direct writes are 64-bit accesses within PMGR resource 1, the CPU cluster performance controller at 0x202220000. The GPU-ID load is at 0x201000020.

| Order | Instance-zero address | Requested value when the calibration row is active |
|---|---|---|
| 1 | 0x2022201b0 | 0x010e1a27333f4bff from the selected row |
| 2 | 0x2022201a0 | 0x0300000008000800 |
| 3 | 0x202220150 | Runtime calibration packed into eight bytes |
| 4 | 0x202220190 | 0x0000000080200306 |
| 5 | 0x202220190 | Read the register, replace bit 35 with the enable Boolean, write back |

If the fourth write reads back exactly as issued, the final enabled request is 0x0000000880200306. A 32-bit archive sample at +0x190 only covers the low half. For a little-endian split dump, +0x194 bit 3 carries register bit 35.

## Reproduce the trace

Run `python3 tools/audit_j81_pmgr_start.py /path/to/kernel /path/to/j81dt` with the decompressed J81 19H394 inputs. The audit verifies both digests. Instruction addresses below are low suffixes of kernel VAs prefixed with 0xfffffff000000000.

* Startup descriptor 17 selects 0x6bccc70. Its type-zero call uses J81 virtual slot +0x6b8, which resolves to 0x6c8a238.
* The constructor at 0x6c8805c copies four 80-byte calibration rows. The initializer at 0x6c885dc matches the effective property value against 12500, 12000, 11500 and 10000. On a match it marks object+0x34e98 valid, saves the row qword and initializes a second qword to all ones. The loop at 0x6c88638 incorporates runtime state into that second qword. The signed tree selects the second row under default settings.
* 0x6c8a258 checks type and calibration validity. With a valid row the subclass issues all four writes irrespective of the enable Boolean. The helper at 0x6c88868 translates logical 0x220xxx to selector 8, instance zero, offset xxx.
* Both branches reach the parent slot +0x6c8 at 0x6c8a2d0. Type zero in 0x6bcfa4c iterates registered instances and uses group 22 (registered at 0x6c88550 with selector 8, offset 0x190). The read at 0x6bcfae8 and mask at 0x6bcfaec preserve the other 63 bits. A missing calibration row can skip the four subclass writes while still reaching the parent path.

## What this changes for GPU bring-up

The Linux page-5-high stalls establish that the page-5 indication alone is insufficient. This path has no direct GPU aperture write, page-5 test or GPU-ready poll. An indirect dependency through CPU or shared power management remains possible. The trace gives no evidence that replaying a CPU calibration table will fix a GPU transaction. Compare existing working and stalled boot captures at the addresses above before considering that hypothesis. A saved final register value alone cannot establish the order of writes or the boot stage. See the [page-5 and GPU-ID evidence](2026-11-19-j81-page5-high-core-stall.md).
