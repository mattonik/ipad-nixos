# J81 and N61 first GPU register access

**T1. Keep the J81 bridge plan.** [Board data and observed writer requests] The 19H394 J81 ADT contains the literal little-endian byte offset 0x40000 in each of two 264-byte properties. The kernel divides property length by eight, consumes each offset/value pair in order and uses the offset in bytes. A fresh comparison against the native 19H394 writer capture matched all 66 tuples, including selector and instance. The N61 Linux driver also matches its own Apple board tree. At physical 0x201f80018 J81 requests **0x80010004** while N61 requests **0x007c7c01**. Combining the tables would overwrite the J81 setting. Sources: ApplePMGR 6bc0998..6bc0a40, 6bd90a8, 6bd3dc8 and 6bd3d38; 19H394 ios-logarchive-j81-records-01/gpu-recent.log; 16H88 DeviceTree.n61ap; e074df51 t7000.dtsi:140–157 and g4p_drv.c:70–76. Kernel VA suffixes omit 0xfffffff000000000.

**T2. MiscACG order differs.** [Code] On J81 the PMGR start path can replay enabled devices before enableACG(true) at 6bcd0ec. The later native SGX acquisition and the early observer's own GFX activation follow that call. N61's executable g4p_drv.c:146–153 resumes ps_gfx before testing and conditionally setting MiscACG bit 0. Its file header describes a different order. The generic Apple method at 6bcf3c8 has two additional conditional paths. On ordinary J81 initialization the supplied mappings/groups predict only a read/modify/write at 0x20e032000. It performs no GFX-state poll or readback of its final write. [Observed] The successful J81 observer found MiscACG=1 with PS=0x300 before its own activation. The single-activation Linux run also reached MiscACG=1. An isolated J81 dependency on write order is unmeasured. See research/2026-11-19-j81-misc-acg-and-page5.md and the packet's board table.

**T3. N61 pre-ID sequence.** [Code] After runtime PM resumes, the driver conditionally sets MiscACG, programs its two bridges, wakes Fender, polls bit 4 clear and delays 10 µs. With read_id enabled and the MiscACG range present it performs a 32-bit CORE_REVISION read at 0x201000020 followed by CORE_ID at 0x201000018. The project's J81 value 0x00070500 is the first word. N61 firmware, MMU and compute work occurs later. [Third-party claim] The driver's author jeroentrappers reported responding registers and successful firmware/PDS work in Orchard issue 61 comment 7060742397. Comment 7060785458 quotes that report. Neither provides raw identity values or an independent reproduction. Sources: g4p_drv.c:63–165,236–288; g4p_boot.c:309–326; issue-61.md. Private report sections 8.11/8.12/8.19/8.20 were unavailable.

**T4. Board difference confirmed in one OS build.** [Offline test] In Apple's 16G102 restore, J96 (T7000) matches the 16H88 N61 address/value layout, while J81 (T7001) matches 19H394 J81. This distinguishes the sampled layouts without comparing different OS releases alone. Both use SGX gate ID 124, GFX PS at 0x20e020320, core at 0x201000000 and Fender at 0x201e00000. Only two physical bridge addresses overlap; only one also agrees in value. The physical base alone is insufficient to select a bridge table. Sources: Apple arm-io/pmgr and sgx nodes in the indicated device trees, tools/compare_n61_j81_bridges.py.

**T5. Localize the compressed stall first.** [Observed in runner reports] A fresh, single-activation Linux boot still stalled with both GPC and page 5 ready. A separate compressed batch with five successful mappings did not return. Its last marker precedes all 66 bridge writes, the GPC sequence, page-5 sample and core read. This does not identify which operation stalled or establish that page 5 was high in that batch. [Inference] The highest-value control returns the same batch just before the core access and preserves the completed poll/page-5 samples. Changing the bridge plan or clock order at the same time would discard that comparison.

[Code] 19H394 6bc0620..624 uses bridge-reg-index (2) plus selector; 6bc06bc..6cc maps that resource and 6bc07dc..800 retains its base. GFX selects 9 then 10. The format-0 path loads the count and the property pointer; virtual +998 ends in STR W3,[X8,W2,UXTW]. There is no implicit multiplication of this offset. N61 Apple properties also have explicit offsets. Its Linux DT simplifies selector 11 to a value list because the Apple offsets there are 4*i. J81 +0x40000 exceeds the entire 0x1000 N61 resource. Sixty-four addresses occur only in the J81 plan and 31 only in N61. [Observed] The iPadOS capture records writer requests; completion or continued retention of every word was not sampled. See research/2026-11-10-j81-ios-corrected-bridge-result.md.

## Ranked follow-ups

1. **Compressed access boundary.** [High diagnostic value] Use the exact run-3 setup, preserve mapping type and timing, end before the first core load and return the final GPC and page-5 values with validity flags. Compare to the existing iPadOS positive capture. If it returns, the failure is narrowed to the omitted tail or its timing. If it still stalls, shorten the batch at existing stage boundaries, starting after the 66 stores. This control retains the previously exercised writes; it introduces no new register address. It still carries the hardware risk of that power/bridge sequence.
2. **Visibility and retention of a J81 bridge word.** [Requests known, retention incomplete] Start with existing independent readbacks of the *same previously readable* selector/offset on both systems, after bridge completion and after GPC. Record physical address, width, boot and phase. A store echo is insufficient. A difference identifies a candidate for tracing. A matching word cannot validate a whole window. No N61 bridge write is warranted.
3. **MiscACG transition relative to GFX.** [Low causal confidence] First compare PS and MiscACG on either side of the activation using existing read-only diagnostics in each OS. Distinguish an already-set bit from an observed rising edge. This can show loss or retention. An ordering intervention would change clock gating and is higher risk; defer until phase-matched evidence identifies a difference. The 19H394 extra group/selector arms are conditional and do not justify targeting their offsets on J81.

The unresolved evidence is the last completed instruction in compressed run 3, runtime retention of individual bridge settings, and an original N61 boot log with both identity words and build/DT provenance. The private report sections or a native N61 trace would help evaluate the claimed A8 mechanism. No register change on J81 follows from the N61 comparison alone.
