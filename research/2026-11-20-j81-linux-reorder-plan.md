# Linux reordered test (Apple's ApplePMGR::start order): plan (prepared 2026-11-20, NOT run; needs a go-ahead per boot)

Trigger: a report from another A8 device (iPod touch 6, T7000, n102) that the first core read stops hanging when MISC_ACG (+0x32000 |= 1), a voltage-manager check (+0x23000 bits 11:8 clear) and SOC_TVM (+0x2d000 |= 1) are set BEFORE GFX power-on, in that order. Our 2026-11-20 write test (`...-linux-tvm-write-result.md`) set the same two bits on J81 but AFTER GFX was on (PS 0x3ff) and after the bridge stores, just before GPC, and the core read still hung. The ordering is the one factor of the claim we have not tested.

Sequence (one shot per boot; any stop is final for that boot): stage tools; snapshot S0 (requires MiscACG 0, +0x2d000 0, GFX off); guarded MiscACG store (0->1); snapshot S1 (MiscACG 1, the other core words unchanged, 0x23000 bits 11:8 clear, else stop: the harness does not enable the voltage manager); guarded +0x2d000 store (0->1); snapshot S2; ONLY THEN the GFX cycle (power on); snapshot A (MiscACG and +0x2d000 must still be 1, else stop before the bridge plan); bridge plan; snapshot B (same check, else stop before GPC); paired GPC/page-5 batch; snapshot C; gated, watchdog-supervised core-ID read (unchanged tool). Snapshots now carry 11 words: 0x20320, 0x32000, 0x1008, 0x4008, 0x1c200, 0x2300c, 0x5004, 0x2d000 plus 0x23000, 0x23004 (vm_sram; the report sees 0 -> 0x14c on T7000, iPadOS 0x147) and 0x2d100 (the report sees 0x00505000 -> 0x004c5003). All three extra words were read on Linux before (2026-11-11), nothing new is accessed. Writers are the same two guarded tools (MiscACG sha 846d9e86..., +0x2d000 sha 998816f9...), one store each.

Tests: `boot/test_j81_observer_reorder_flow.py` passes: full flow; core gate skip; unexpected checkpoint; and the stops pre-state (stops after 1 snapshot, nothing written), voltage-manager bit set (before the TVM write), writer refusal, state lost across the cycle (before the bridge), lost across the bridge (before GPC), each with the GFX cycle or GPC batch not started where promised. `--verify-only` passes. Artifacts: `artifacts/live/private/j81-linux-reorder-experiment/`; diff `2026-11-20-j81-linux-reorder-campaign.diff`.

Outcomes: ID returns (expected 0x00070500) => the missing piece was ordering (Apple's start order before GFX power-on), a strong result that also corrects our earlier recipe. Hang => ordering is not it for A8X; the read-back words show what the stores did to vm_sram and +0x2d100 on J81. A stop at S0/S1/S2/A/B tells which assumption fails (for example that the GFX cycle resets the PMGR bits) and costs no core read.

Risk: same class as before: two PMGR stores and a core read under the 20 s watchdog, RAM-only Linux.
