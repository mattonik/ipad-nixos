# J81 provider calls before GPU-ID on 19H394

**T1. Provider identity [code].** The receiver loaded from [X27] is the matched SGX child. The normal publisher constructs an AppleARMIODevice and stores its AppleT7001IO controller at child+0x88. The child translates gate-array index 0 to GFX ID 0x7c in *both* calls. These are two objects, each with slots +0x568 and +0x570. The child derives from IOService. The controller derives from AppleARMIO, whose base is IOPlatformIO. This corrects the older superclass attribution. Address suffixes below omit 0xfffffff000000000. Factory 5b29154, child initializer 5b2a108, AGX cast/store 6683274..6683378; 19H394 J81 ADT /arm-io/sgx.

**T2. Effects [code].** Slot +0x568 requests active state 15 for the GFX domain at 0x20e020320. On an increasing transition it can program the minimum, target and automatic-management fields, poll actual state, and apply 33 pairs to each of two bridges. Slot +0x570 runs a status query under the PMGR command gate. It tests bit 8 of that same word and, if clear, tests bit 9 on a second read. Its output goes to the caller's stack. The requested enable argument is dropped by this callback. The resulting Boolean participates in later cleanup. No additional GPU power-on, reset, GPU-QoS, SPR, SMC or SEP request was identified on this ordinary board path. Conditional diagnostics, workloop synchronization and runtime substitutions limit that conclusion. See the dispatch and effect rows below.

**T3. Successful hook [observed and inferred].** On iPadOS boot 846527FB, the manual sequence entered with GFX PS=0x300, page 5 clear and MiscACG=1. It reached 0x3ff, completed its own bridge/GPC sequence, sampled page-5 bit 30 high three times and returned GPU-ID 0x00070500. The native G4G calls occur later. Their invocation and caller-local output cannot be prerequisites for this earlier read. Startup or another client could supply shared state. The observer itself supplies activation, bridges and Fender. Linux boot 36e22c25 had the same GFX endpoint and both page-5 samples high, then produced no ID before the watchdog reset. Its GFX trace includes an intervening power-off and second activation. See the phase comparison below. The PMGR software cache at +0x19110 and the callback vptrs were not sampled on the early success.

**T4. Guards [code, inferred defaults].** The normal J81 first initialization predicts flags 0x07 in bits 0–4, accelerator capability byte 1 and Fender map index 1. That path issues all three Fender writes, polls +0x1000 bit 4 clear and calls the delay helper with 10 µs before identity. First-init state, boot args and the full flags byte on the successful early boot are unmeasured. The manual observer has its own poll and logging schedule. Detailed sources and guard addresses appear below.

**T5. Runner priority [inference].** Compare the extra Linux power transition first. The positive iPadOS boot bypasses the native callbacks and the ordinary MIN write. A separate Linux-only history read or a second raw power-enable write has little discriminating value. The five observations below identify which questions each result can answer.

## Phase comparison

[Code and observed] The actual early observer (SHA-256 3f409df104a56f7c7ad9fd3b8b75fcbaed66e6e094678daac28e0a0ade5e8671) guards on old PS=0x300, requests 0xf, polls ACTUAL=15, writes (successful poll & ~0x300) | 0x10000000, then requires a fresh PS read of exactly 0x3ff. It enters two 33-write bridge loops. Its Fender poll requires (raw & 0x1f)==1. The observed GPU-ID establishes that all these checks passed. The exact successful PS poll word was not printed. No separate MIN write or off/on cycle appears in this manual acquisition. Compare observer offsets 41d0..42b0 and 42e0..4350 with the five records in from-builder/2026-11-19-j81-ios-pregpc-miscacg-run-result/evidence. This success weakens the proposed necessity of native MIN programming or using the saved pre-poll TARGET for auto-enable on each acquisition.

[Observed] Linux 36e22c25 records active/off/active in gfx-request.log: target requests 0xf, 0xf0, 0xf, polls 0x3ff, 0x300, 0x3ff. Both active requests issued auto_word=0x100000ff. Its kpoll.log records GPC raw 1, 11 polls, page 5 high at both samples. Clock words, the five bank enables, MiscACG and TVM precede this cycle. The native clock callback can therefore explain *how* shared hardware reaches some of the same endpoints, without explaining *why* the successful hardware transaction occurs. Linux has no corresponding Apple object/cache bookkeeping or caller Boolean. Those software differences alone do not imply an extra hardware transaction. The effective clock-reset state, ordering and translation at the core load are incompletely observed. [Pinned Linux setter, lines 48–83](https://github.com/HoolockLinux/linux/blob/6831bc701a6ce059e71e5aaa9488c9195bea6927/drivers/pmdomain/apple/pmgr-pwrstate.c#L48-L83)
