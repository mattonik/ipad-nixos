# J81: prior iOS GPU analysis versus the 19H394 kernel

Offline comparison of the local `ios15-kernel`, previously associated with
15.8.8/19H422, and the kernel extracted for the tested 15.8.5/19H394 build.
The complete files differ; this note compares defined ranges rather than
assuming the releases or their runtime behavior are equivalent.

Both outer Mach-O images locate `__PLK_TEXT_EXEC` at virtual address
`0xfffffff005a9c000`, file offset `0xf48000`, size `0x1258000`. The **entire
prelinked executable range is byte-identical**, SHA-256
`de22aa33cf0fc11247ab2ced304110954a1d926415fb815c21090b899669afea` in
both. The previously extracted AGX code (file offset `0x1b18000`, length
`0x45960`) is likewise identical, SHA-256
`9543debbf2d4bdb80c44cd2c6e9d2bb651631ce9d3561cd8b63c7bd9f0269d50`.
Each complete kernel contains that AGX byte sequence exactly once.

The `__PLK_DATA_CONST` segments differ overall. Specific recovered vtable
entries were therefore checked independently and match at the same virtual
addresses in both files:

| Static vtable | Checked slots and target addresses |
| --- | --- |
| G4G accelerator `0xfffffff006f2f2d0` | `+0x2a8` → `0xfffffff00668322c`; `+0x2b0` → `0xfffffff0066990ac`; `+0x848` → `0xfffffff00669afa8`; `+0x850` → `0xfffffff00669aff4` |
| Firmware controller `0xfffffff006f2de28` | `+0x78` → `0xfffffff00668f2d4`; `+0x98` → `0xfffffff00668f770`; `+0xa0` → `0xfffffff006689cc0`; `+0xc0` → `0xfffffff006690328`; `+0x5a0` → `0xfffffff00668735c` |
| Fender `0xfffffff006f2fee8` | `+0` → `0xfffffff00669bbac`; `+0x10` → `0xfffffff006698d94`; `+0x18` → `0xfffffff006698f24`; `+0x78` → `0xfffffff00669c3e4` |
| T7001 PMGR `0xfffffff006fe5e28` | `+0x980` → `0xfffffff006bd0478`; `+0x988` → `0xfffffff006bd04f0`; `+0x998` → `0xfffffff006bd3d38` |

The five-byte selector jump table at `0xfffffff0057c3181` also matches:
`00 1d 31 45 4b`. These comparisons strengthen application of the prior
[GPU lifecycle](2026-11-09-j81-ios15-firmware-lifecycle-order.md),
[performance-buffer](2026-11-09-j81-ios15-perf-buffer-consumer.md), and
[PMGR writer mapping](2026-11-10-j81-page5-writer-mapping-audit.md) analyses
to this 19H394 kernel. They do not prove those paths execute at runtime,
that static vtables are the active classes, or that other data and hardware
initialization match. In particular, the lifecycle ordering is still an
inference, and this does not identify an RGX-ready clock or voltage.

Full-image SHA-256 values are `832cd980f257e6205b8ec131abea2a8470f3a3455f2c7039c890a091149c7389`
and `c3507666766775dc854d5bcf6c375e6651ac8b2d1adb13d06331c60deb6a0008`,
respectively. Kernel binaries remain private. No device test was performed.
