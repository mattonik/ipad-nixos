# J81 GPU firmware boot: runbook

How to reproduce the runs in [`j81-gpu-firmware-boot.md`](j81-gpu-firmware-boot.md). One device (iPad Air 2, J81), one run per boot. Apple data (the firmware LDR, kernelcache, the extracted bridge table) is private and never committed; paths below assume the git-ignored `artifacts/live/private/`.

## What you need

- The iPad in DFU with the Linux observer kernel (`a2dda271…`, release 7.3.0-rc1) loadable: palera1n `--pongo-shell`, `boot/Pongo.bin`, the always-on bundle `artifacts/live/private/j81-dwialwayson-bundle-20261122/m1n1-linux.bin`, ssh key `artifacts/live/ssh/ipad_ed25519`, device at `root@172.16.42.1`.
- The GPU module built on the Linux builder: `tools/builder.sh build --wait --who gpu --impure --expr "import $PWD/kernel/j81-gpu/build.nix { repo = $PWD; }" -o artifacts/live/gcroot-j81-gpu-hNN` (commit first; the module needs `kernel/j81-gpu/gfx-bridge-plan.h`, generated by `gen_bridge_header.py` from a private `gfx-bridge-plan.bin`). Latest: module h47 (`542c1df8…cd8d`).
- The watchdog supervisor with the J81 mode: `artifacts/live/gcroot-gpu-watchdog-supervisor-j81/bin/gpu-watchdog-supervisor` (sha `039d669b…`). Status lines must stay under 480 bytes; the module caps them.
- The firmware LDR: the `__TEXT.__const` section of `com.apple.AGXFirmwareKextG4G` from the 19H394 kernelcache (117,684 bytes, sha256 `55018c7e…092c2f`), kept at `artifacts/live/private/a9tools-j81-19h394/AGXFirmwareKextG4G.__TEXT.__const.bin`.

## One cycle (per boot)

1. User puts the iPad in DFU, then (host): `cd <repo> && sudo boot/vendor/palera1n-macos-arm64 --pongo-shell --override-pongo boot/Pongo.bin`; wait for the Pongo shell prompt.
2. Load m1n1 (the loader times out at the bootm handoff, which is normal):
   `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib nix develop -c python3 boot/load_m1n1.py artifacts/live/private/j81-dwialwayson-bundle-20261122/m1n1-linux.bin`
3. Wait for ssh, then the preflight: `boot/j81_preflight.sh gfx-request-observer` must end with `GO: gfx-request-observer`.
4. Run (zsh needs an array for the repeated `--write`; logdir must not exist; logdir first):
   ```
   W=(); for s in <steps>; do W+=(--write $s); done
   /opt/homebrew/bin/python3 boot/j81_gpu_run.py artifacts/live/private/j81-gpu-run-<name> \
       --module artifacts/live/gcroot-j81-gpu-h47/j81-gpu.ko \
       --supervisor artifacts/live/gcroot-gpu-watchdog-supervisor-j81/bin/gpu-watchdog-supervisor \
       --f3a-blob artifacts/live/private/f3a-blob-20261126d/j81-f3a.blob "${W[@]}"
   ```
   A stage line with `INCOMPLETE` means the iPad reset; do not retry that boot.

## Build the firmware blob (offline, once per layout)

`/opt/homebrew/bin/python3 boot/j81_f3a_build.py <LDR> <new private dir> 0x8000b3c820000000 1` (third argument: config `+0x2f0`, thread 1 `{sp, pc}` with sp high; fourth: `1` fills the MMIO window table and tells the module to map the pages). It runs `tools/j81_meta_ldr_layout.py` (Apple's loader rules), builds the heap image (root, state, config, list-head blocks, rings, ConfigRAM word template) and a header, and prints the blob sha256 and the heap checksum that `f3load` must report in the status (`s<checksum>`). Blob d: sha256 `d9398bc5…a021`, checksum `7e5703a0`.

## Step reference (module h47)

Sequence steps (the F2 recipe; all need state `identified`, i.e. after the batch identity step, and are used in this order): `w1 w2a h0 h1 h2 h3pb h4 h5 h6 <list> h8 h9 h10 h11`.

| Step | What it does |
|---|---|
| `w1`, `w2a` | first RGX writes (probe write, SOFT_RESET stage/unwind), prerequisites of the h-steps |
| `h0`..`h2` | GPC state 0 request and wait, Apple's setter |
| `h3pb` | GFX PS power cycle, **66 bridge stores re-applied**, second state-0 request (Apple's order) |
| `h4`, `h5`, `h6` | `+0x10 = 0` with read, `+0 = 0x40000000` |
| `h7a` | Apple-order ConfigRAM list (asserts, SLC pair, release, META_BOOT) for F2 runs |
| `h7f1` / `h7f2` | the blob's ConfigRAM list without / with the final SOFT_RESET release (the real stream, 31 words) |
| `h8` / `h8n` | the real `+0x20000 = 0` store / skip it |
| `h9`, `h10`, `h11` | wait idle, state 1 request (`+0x1000 = 0x11`), wait and read `0xbf8`, `0x3800..0x3808`, `0x20`, PMGR PLL bit |
| `f3alloc`, `f3upload`, `f3load` | allocate the 8 MiB region, copy the blob (wrapper pseudo-step), build GPU tables, verify the walk, checksum, snapshot |
| `f3poll` | 250 ms slice: poll the event ring write index (heap `0x4c010`) |
| `f3sum`, `f3chg` | heap diff vs the snapshot: counts and the first words / all changed words, 4 per call |
| `f3meta`, `f3metaA/B/C/D` | META slave-port reads: T0/T1 ENABLE/STATUS and SEG2; SEG0/1; SEG3 + caches + PRIVEXT + clock control; coremem word match; TXCATCH0..3 |
| `f3pc`, `f3pch` | thread 0 PC samples (3 x 100 ms, plus TXSTATUS/DEFR/TIMER); 200-sample histogram |
| `f3regA/B/C` | thread 0 D0 / D1 / A0+A1 registers through the core-register port (snapshot) |
| `f3coreA..F` | 8-word dumps of core memory at `0x80009c40/60/80/a0`, `0x8000a000/20` |
| `f3tb`, `f3timer`, `f3usc` | AIC timebase page (64 words twice) / first two words twice / USC slot registers `0xe100`, `0xe200` |
| `f3t1` | thread 1 ENABLE/STATUS/PC |
| `f3halt` | **writes** `TXENABLE = 0xfffffffe` (halt thread 0), reads PC/PCX/status |
| `f3t1start` | **writes** thread 1 SP and PC and `T1ENABLE | 1` |
| `f3kick` | **writes** Fender `+0x14 = 7` and RGX `0xb00 = 0x10` |
| `f3bif` | reads `0x12b0` (BIF fault) |

## Recipes

- **F2 (walk only), module h32 or later:** `w1 w2a h0 h1 h2 h3pb h4 h5 h6 h7a h8 h9 h10 h11`. Expect h11: state 1, `h_x[0]=1`, `h_slc=00300001/00035500/0`, `h_core=00070500`.
- **F3a-0 (memory only):** `f3alloc f3upload f3load`. Expect `w7` (`w15` with windows) and the blob checksum.
- **Firmware boot (run 54 and later):** `f3alloc f3upload f3load w1 w2a h0 h1 h2 h3pb h4 h5 h6 h7f2 h8 h9 h10 h11` then 20 x `f3poll`, then diagnostics, then one-shot writes last.
- **Timeline / diagnostics:** `... f3pch f3regA f3regB f3regC f3pc f3sum f3meta f3bif`.
- **Halted snapshot:** `... f3pc f3halt f3pc f3regA f3regB f3regC f3meta f3sum f3bif`.
- **Thread 1 and kick:** `... f3t1start f3poll x4 f3kick f3poll x8 f3t1 f3pc f3sum f3chg f3meta f3bif`.

## Status field glossary

`f3=<phys>,<loaded>,w<walk bits>,s<heap checksum>,pc<page catalogue>,n<words>,e<ms polled>,<wr>/<ev ctl>,<record words>,bif<0|1>:<fault>`; `f3x=c<changed words>,<off>:<val>,…,s<checksum> m=<T0ENABLE,T0STATUS,T1ENABLE,T1STATUS,SEG2 base,limit>`; `mP=pc,pc,pc,TXSTATUS,TXDEFR,TXTIMER,tries,err`; `mH<n>=<pc>*<count>,…`; `mHL=txenable,txstatus,pc,pcx,pc'`; `mX/mY/mZ=` D0 / D1 / A0,A1; `mT1=` thread 1; `mKK=` kick; `mS1=` thread 1 start; `mTB`/`mUS`; `chg@<n>=` changed words.

## Recovery

If a run ends `INCOMPLETE` the iPad resets: DFU again, nothing to clean up (the module and the 8 MiB region live only in RAM). Mailbox, builds and research logs live outside the device.
